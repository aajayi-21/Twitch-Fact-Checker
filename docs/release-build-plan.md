# Release Build Plan: v0.1 on the Chrome Web Store

*Written 2026-11-13, from a release-readiness audit of `master` at `10201e9`. The
decisions in the first table were made by the owner the same day. Companion to
[`viewer-app-build-guide.md`](viewer-app-build-guide.md) (what was built) and
[`store/submission-checklist.md`](store/submission-checklist.md) (the account-holder
steps). Nothing here is published or submitted: the owner's instruction not to deploy
publicly yet still stands.*

**Goal.** A viewer installs Doxa from the Chrome Web Store (and Edge Add-ons), adds an
Anthropic, OpenRouter, OpenAI or Gemini key, and gets correct, sourced verdicts on a real
Twitch, YouTube or Kick stream. Spending stays inside their limits, and every failure
tells them what to fix. The optional local backend is safe to run and installs with one
command.

**Where it stands.** 1442 backend tests and 337 extension tests pass. Both store
packages build (Chrome 8.6 MB). The browser engine has gone from install to verdicts
with Anthropic and OpenRouter on a recorded 43-second clip played through the real tab
capture, but never on a real stream. The audit found the defects below.

## 4. Phase 1 — Local backend security ✅

**Built 2026-11-13** on branch `feat/backend-security`. Differences from the plan below:

- **One guard instead of per-route checks.** `backend/app/origins.py` is an ASGI
  middleware on both servers that checks every HTTP request and WebSocket handshake.
  Allowed: no `Origin` (non-browser clients), `chrome-extension://<id>` with the ID in
  `ALLOWED_EXTENSION_IDS`, and the server's own pages (Origin equal to
  `http://<Host>`, rather than a port list). `null` is allowed only on `/ws/events`,
  which was confirmed read-only. Refused requests get a 403, refused sockets close 1008.
  This also covers 1.5's body-less `POST /setup/twitch/device`, so that route keeps its
  shape.
- **The development ID is `hbgnggamecjggjhmlnpfkcpocopcbokm`.** Only the public half
  of its key pair exists; it is in `extension/manifest.json`, and the store build
  strips it. `scripts/lib/chrome_harness.mjs` derives the ID from the key.
- **1.4 needed a new endpoint.** The welcome flow's sample check called `/debug/text`,
  so it moved to an always-on `POST /setup/test-check` (shared code in
  `app/text_check.py`) that returns the result without pushing verdicts into live
  sessions. `/debug/text` and `/debug/stt/fail` are off unless `DEBUG_ENDPOINTS=true`;
  `run.sh` does not turn them on.
- **Extra fixes found on the way.** The device-poll route also called `validate_token`
  unguarded (another bare 500). A 200 from Twitch with a missing field is now a 502
  with the reason, not a `KeyError`.
- **A refused extension is told why.** The 403 names the extension ID and the setting
  to add it to; the popup shows "Backend refused this extension" with its own ID, and
  the app shows the backend's message.

Verified: 1483 backend tests (32 new for the guard, 4 for the sample check, 6 for the
Twitch errors); 337 extension tests; the app e2e against a real backend (30/30,
including Start → "capturing" through the offscreen document's WebSocket with the
fixed ID) and against the fake one (82/82); the store package's no-key demo (13/13);
and by hand: a website origin gets 403, the dev extension 200, `/debug/text` 404.

### 1.1 Origin check on `/ws/audio` (blocker)

`backend/app/ws.py:139` accepts any Origin. CORS does not apply to WebSockets, and
TrustedHost passes because the Host header is still `127.0.0.1`. So any website the user
visits can connect. With the default `session_preempt_scope="global"`, the connection
alone kills the user's live session; a transcript-format hello then spends the user's
API credit on invented claims. On the streamer server the page can name the channel and
put its own claims in front of the chat bot.

- Move the Origin rule out of `streamer/routes.py:59` into one shared module
  (`app/origins.py`) used by `app/main.py` (CORS), `app/ws.py` and `streamer/routes.py`.
- `/ws/audio`: allow the listed extension origins, and a **missing** Origin (the ingest
  CLI is not a browser, and browsers always send one on a WebSocket). **Reject `null`**:
  a sandboxed iframe on any website sends `null`.
- `/ws/events`: keep allowing `null` and a missing Origin for OBS browser sources, but
  only while that socket is read-only. Confirm it accepts no commands; if it does, move
  them behind the extension or panel origins.
- Close with code 1008 and log the refused Origin once per minute.

### 1.2 Allow-list of extension IDs (should fix)

`app/main.py:41` trusts `chrome-extension://` with any 32-letter ID, and any
`localhost` port. Any other installed extension, or any local dev server, can call
`/setup/credentials`; an empty key deletes the stored one (`app/setup.py:713`).

- New setting `ALLOWED_EXTENSION_IDS` (comma-separated). It defaults to Doxa's IDs, and
  the regex for any extension goes.
- **Fix the development ID:** generate a key pair once, put the public key in
  `extension/manifest.json` as `key`, and keep the private key out of the repository.
  The unpacked extension then has the same ID on every machine.
  `scripts/build_extension.py` strips `key` from the store package.
- The store item's ID is known only once the first draft is uploaded (a step only you can
  take; see Phase 9). Add it to the default list then. Until then, anyone running the
  store build against a backend sets `ALLOWED_EXTENSION_IDS`.
- Localhost origins: keep only the ports the backend itself serves (the dashboard and
  console pages), not every port.
- Tests: a foreign extension ID, a foreign localhost port, `null` and a website origin are
  each refused on HTTP and on both sockets; the listed ID and a missing Origin (CLI) work.

### 1.3 Preempt only after a valid hello (should fix)

`registry.preempt_on_accept()` runs before the hello is read (`app/ws.py:149`), so any
connection that opens, even a refused or malformed one, ends the live session. Preempt
inside `register()` after the hello parses, under every scope.

### 1.4 Debug endpoints off by default (should fix)

`debug_endpoints: bool = True` (`app/config.py:470`). `/debug/text` runs paid checks and
pushes verdicts into live sessions. Default to `False`; `run.sh` and the e2e scripts that
need it set `DEBUG_ENDPOINTS=true`.

### 1.5 Smaller backend fixes

- `streamer/routes.py:660,727`: wrap `persist_credentials()` the way `app/setup.py:718`
  does. A `ValueError` (newline in a value) becomes 400, and an `OSError` becomes 500,
  each with a message.
- `streamer/routes.py:671`: `POST /setup/twitch/device` takes no body, so any website can
  fire it without a preflight and restart a pairing. Require a JSON body.
- `streamer/twitch_auth.py:191`: a 200 response with no `access_token` raises a bare
  `KeyError`; turn it into the module's own error with a message.

**Done means:** a test page served from another origin cannot open either socket, cannot
end a session, and cannot change a key; the extension and the ingest CLI still work.

## 5. Phase 2 — Spending and error reporting (extension) ✅

**Built 2026-11-13** on branch `feat/spending-errors`. Differences from the plan below:

- **A missing model is a third fatal stop.** Providers now report a 404 (and
  OpenRouter's "not a valid model" / "No endpoints found", OpenAI's `model_not_found`)
  as `MODEL_UNAVAILABLE`, which ends the session with `model_unavailable`. The plan's
  "Model … isn't available at OpenRouter" wording became "<provider> cannot run the
  model "<id>": <reason>. Choose another model under AI provider."
- **How the reason travels.** The pipeline emits the fatal frame and disposes itself;
  the offscreen document ends the session with `ERR_KEY_REFUSED`, `ERR_NO_CREDIT` or
  `ERR_MODEL_UNAVAILABLE` and the sentence in `session.errorDetail`. The overlay shows
  it, the popup shows it in place of its stock copy, and Home shows "The last session
  stopped: …" with a link to AI provider (the app now reads the session record).
- **Warnings while running.** "Claim detection is failing" and "limit reached" go into
  `session.warning`, which the popup shows during a session; `gate_recovered` and
  `budget_resumed` clear it.
- **The overlay shows messages written for viewers as sent** (`quota_cooldown`, the
  budget notices, the fatal stops). Before, `quota_cooldown` always read "API quota is
  cooling down", which also hid the backend's own reasons.
- **Billed failures.** `attachUsage` / `readBilled` in `providers/common.mjs` put the
  usage of every answered call on the error, through Anthropic's paused turns and
  Gemini's fallback chain; usage rows carry `outcome: "failed"`.
- **Resumed checking is announced** (`budget_resumed`) after a new day or month or a
  raised limit.
- **Unpriced models** are named once per session over the stream, appended to the
  monthly-limit notices, and shown on the spending-limits card and Home. Totals with
  unpriced calls read "≈ $0.42 + unpriced".

Verified: 356 extension tests (19 new); `run_browser_engine_e2e.mjs --bad-key` (new,
free): a deliberately invalid key stored directly, a session on the recorded stream,
Anthropic's real refusal ends it with the reason, nothing billed, Home and the popup
say why (11/11); the app e2e and the store package's no-key demo.

### 2.1 A refused key or no credit stops the session (blocker)

`engine/pipeline/browser_pipeline.mjs:493` sends auth and billing failures as
`quota_cooldown`. The overlay (`content/overlay.js:438`) replaces the message with fixed
"cooling down" text, the popup keeps saying Live, and the pipeline retries every
5 minutes forever.

- New error codes `key_refused` and `no_credit`, sent with `fatal: true` and the
  provider's own reason ("Anthropic refused the API key: …").
- The service worker ends the session the same way Stop does, so capture is released.
- Overlay, popup and Home show the reason with a link to the AI provider screen.
- Rate limits (429) keep the existing cooldown.
- The backend engine already has the matching frames; check that its codes map to the
  same messages.

### 2.2 Claim detection failures are visible (should fix)

Gate errors only reach `console.warn` (`browser_pipeline.mjs:504`). A typo in the gate
model means no claims, ever, while the popup shows Live.

- Count consecutive gate failures. After 3, emit a non-fatal `gate_failing` error with
  the reason; the overlay and popup show "Claim detection is failing: …". The first
  success clears it.
- A 404 or "model not found" on either stage is fatal, with "Model `<id>` isn't available
  at OpenRouter", because nothing will recover it.

### 2.3 Billed calls that then fail are counted (should fix)

`providers/anthropic.mjs:243` throws on `max_tokens`, `pause_turn` or a refusal after the
paid response arrived. `finalizeVerdict` errors and the timeout retry
(`browser_pipeline.mjs:412-427`) send no usage either. So spend and history undercount.

- Provider errors carry the usage of the response that arrived (`ProviderError.usage`).
- The pipeline emits a `usage` frame for every billed call, success or not, with
  `outcome: "failed"`.
- `checksToday` moves from memory into the session's ledger counters, so a restarted
  worker resumes the right count.

### 2.4 Limits apply live and reset on time (should fix)

Limits and spend are captured once when a session starts (`background/service_worker.js:343`).
Changing a limit mid-session does nothing, `spent` never resets after midnight or the end
of the month (`browser_pipeline.mjs:518`), and a failed history read starts spend at $0
(`service_worker.js:345`).

- The service worker passes budget changes (`storage.onChanged` for the limits keys) to
  the running pipeline through a new offscreen message. Raising a limit after a stop
  resumes checking; lowering it applies at once.
- The pipeline keys its counters by local day and month and resets them when either rolls
  over.
- A failed history read refuses to start ("Couldn't read your spending so far; try
  again") instead of assuming $0.
- One unit of counting for the daily limit: **checks, not HTTP calls**. Today History
  counts calls (`ledger/queries.mjs:529`) while the pipeline counts checks, so a Gemini
  fallback (2–3 calls) can hit the limit early after a restart.

### 2.5 Unpriced models: warn only (decided)

The monthly limit covers only models in `ledger/pricing.mjs` and costs that OpenRouter
reports. Per the decision, an unpriced model keeps counting $0. To make that honest:

- The AI provider screen, Home's spend card and the 80 % notice say "The monthly limit
  doesn't cover `<model>`: its price isn't known. The daily check limit still applies."
- History marks those calls "not priced" (already does) and the monthly total says
  "+ unpriced calls".
- Phase 5 adds OpenAI and Gemini prices, so this only affects typed custom models.

**Done means:** unit tests for each of the above, including a month rollover mid-session
and a budget raised mid-session; the browser e2e shows the key-refused path end the
session with the right text (using a deliberately bad key, which costs nothing).

## 7. Phase 4 — Streamer bot safety fix

Streamer mode isn't part of v1, but this one breaks a stated invariant ("every consent
proof is checked on every post"), so it is fixed now.

- `streamer/chat/bot.py:433`: `approve()` re-runs the same checks as an automatic post
  (consent proofs, mute, mode, latch) before `_post`, and records a refusal with its
  reason.
- `_cmd_off`, `_cmd_mute` and `_cmd_disable` (`bot.py:746,754,853`) clear `review_queue`,
  recording each dropped item as `skipped`, with the command that cleared it as the
  reason.
- `streamer/chat/transport.py:493`: the transport also refuses a leading `/`, `.` or `!`,
  so the guard holds even if a future caller skips `sanitize_for_chat`.
- Tests: approve after `!fc off`, after `!fc mute` and after the bot is demodded each
  post nothing.

## 9. Phase 6 — Backend one-command install

The target is a stranger with `uv` installed running the companion with one command and
no clone:

```bash
uvx --from git+https://github.com/<owner>/<repo>#subdirectory=backend doxa
```

- **Entry points** in `backend/pyproject.toml`: `doxa` (the viewer backend, today's
  `run.sh`), `doxa-streamer` (today's `run-streamer.sh`), and the existing
  `fact-checker-ingest`. Each binds to `127.0.0.1` by default, as `run.sh` does.
- **Data in a per-user folder.** `.env` and `fact_checker.db` resolve next to the source
  today (`app/config.py:27,153`). Installed, that is inside the uv cache, so keys are lost
  when it's cleaned. Use `platformdirs.user_data_dir("doxa")` when not running from a
  checkout. A checkout keeps using `backend/.env`, so nothing changes for development.
  Print the data folder at startup.
- **Lighter default install.** `faster-whisper` (with ctranslate2, onnxruntime and av) is
  installed for everyone, and the default `STT_BACKEND=faster-whisper` downloads a model
  at startup and fails offline. Move it to an extra, `doxa[stt]`. Without the extra, the
  default becomes `STT_BACKEND=none` (transcript sessions only, which is what the
  extension's "This browser" speech uses), and the extension says so if the user picks
  backend speech. A checkout's `uv sync` keeps the extra.
- **Dependency floors.** uvx doesn't read `uv.lock`. Raise `fastapi` to the first version
  with the strict content-type default the cross-site protection relies on, and check
  the other floors against the lock.
- README: the uvx command first; `run.sh` stays as the development path.

**Done means:** in a clean container with only `uv`, the command above starts the
backend, the extension connects with its listed ID, a transcript session returns a
verdict, and a restart keeps the key.

## 11. Phase 8 — Real-stream validation week

Nothing so far has run on a real stream, and that is the biggest remaining unknown.

- **A week of ordinary viewing** with the store build (`dist/chrome`, loaded unpacked) on
  Twitch, YouTube and Kick, plus Rumble if it can be reached. Read every verdict. Record
  wrong verdicts, missed obvious claims, opinions that got checked, overlay placement
  problems, and spend per hour.
- **YouTube and Rumble channel detection** against the live sites. They can't be reached
  from the development shell, so this happens in your own browser:
  `node scripts/check_page_identity.mjs --headed URL…`.
- **Retention:** leave it installed across a day and confirm the daily sweep ran.
- **Other GPUs:** only Intel Arc has been tested. Get at least one NVIDIA and one Apple
  machine through the speech self-test (the benchmark page produces a shareable report).
  An AMD report too, if available.
- **Exit criteria:** no wrong TRUE/FALSE verdict that a viewer would screenshot; no
  session that silently stopped working; spend inside the default limits.
